# Fixed regression corpora

These files are acceptance criteria, not examples generated by the parser being tested. CI runs them as an explicit gate before the complete suite, on Python 3.10 and 3.12. Local runs must use the project's Slurm test runner on this cluster.

| File | Cases | Provenance |
| --- | ---: | --- |
| `honest_sentences.json` | 55 | Authored, review-seeded sentences supported by the fictional corpus profile, including the offline-demo version/modifier regression. |
| `invented_sentences.json` | 34 | Authored adversarial claims, including the reported Python/PyTorch/ROS bypasses, bare-word counts, ordinals, and reflected metadata. |
| `pay_strings.json` | 50 | Authored representative patterns with independently specified expected USD base-pay ranges, including every supplied bonus example. |
| `public_pay_excerpts.json` | 50 | Short, verbatim base-pay excerpts from separate public Figure and Nuro postings, retrieved on 2026-11-16. Each entry includes its posting URL and frozen expected range. |

The review supplied examples rather than the complete original 54/15 sentence sets. The authored sets above are not presented as those original review datasets. Public salary excerpts retain at most 25 words per posting; their source URLs are attribution, not network dependencies. Tests never fetch these URLs.

For a regression, add a case with its evidence and intended result before changing production code. Keep prior expected results. A change to an existing expectation needs an explanation of why the old expectation was wrong; do not tune fixtures to make a heuristic pass. The parser must pass the positive, adversarial, authored-pay, and public-pay sets together.

The numerical fixtures intentionally distinguish documented tool versions from measurement claims. A bare tool name does not establish arbitrary versions. Version numbers cannot authorize percentages, deployment counts, or unrelated quantities; scalar source numbers from version labels are excluded from metric evidence.
